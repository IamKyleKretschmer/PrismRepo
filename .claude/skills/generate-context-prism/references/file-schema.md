# File schema: Prism solution cross-repo context

This schema defines the **solution layer (L0)** of a Prism solution: a thin,
link-led context tree that orients an agent across every repo declared in
`/.prism/config/repos.yml`, then routes into the relevant repo context. Keep it
lightweight — summarise and link; never restate repo documentation here.

The generated tree lives in this `sdd` repo's `/.context/` folder:

- `.context/README.md` — entry point and reading order
- `.context/manifest.yml` — the repo index with roles and load triggers
- `.context/solution-overview.md` — what the solution does and how repos relate
- `.context/repo-map.md` — per-repo summaries that link into repo context
- `.context/integration-points.md` — cross-repo contracts/interfaces (optional)

Every generated file begins with:

> Auto-generated by generate-context-prism skill. Verify before committing.

## Repo roles

Each repo carries a role drawn from `/.prism/config/repos.yml`. Always make the
role explicit so agents know where they may write code:

- **core** (`coreSolutionRepos`) — owned, local on disk, and code is written
  here. Link to the repo's full `/.context/` and `AGENTS.md`.
- **context** (`contextRepos`) — read-only; architectural and interface
  integration knowledge only. For remote repos, link only to the declared
  `contextPath`; for local repos, link to `contextPath` when present or the
  relevant local context files. Summarise only what the solution consumes
  (contracts, APIs, conventions).

## Linking, not restating

Defer to each repo's own context. Link to a core repo's `/.context/` and
`AGENTS.md`; link to a context repo's declared `contextPath` or relevant local
context files. Summarise in one or two sentences. Never copy module maps,
patterns, or code into this layer. For remote context repos, link within the
declared `contextPath` only.

## `.context/README.md`

5-15 lines. States that this is the solution-level context layer, names the
source manifest (`/.prism/config/repos.yml`), and gives the reading order:
solution overview → repo map → the target repo's own `/.context/`.

## `.context/manifest.yml`

A small index. For each repo record: `name`, `role` (`core` | `context`),
`path` or `source`, `contextPath` (when applicable), a one-line `summary`, a
`context-link`, and optional `load-when` hints so agents know which repo to
open for a task. Remote context repos must have a `contextPath`.

## `.context/solution-overview.md`

Short. Required sections:

1. **Mission** — 2–4 sentences on what the solution does end to end.
2. **Repo landscape** — the core repos and their responsibilities, plus the
   context repos and what each supplies.
3. **Relationships** — how the repos depend on or integrate with each other.
   An optional Mermaid C4 System Landscape diagram may illustrate this.

## `.context/repo-map.md`

A table or short section per repo. For each: role (core/context), brief
purpose, key components/entry points (named, not described in depth), and
links to the relevant context. Core repos may note where code is typically
written; context repos note the interfaces consumed.

## `.context/integration-points.md` (optional)

Generate only when there is evidence of cross-repo contracts. Capture the
interfaces between repos (APIs, events, shared contracts, auth), linking to the
owning repo's source of truth. Omit the file entirely if there is no evidence.

## `AGENTS.md` (repo root) — required `## Repository Context` section

The `sdd` repo's root `/AGENTS.md` is the entry point into this layer. It must
contain a `## Repository Context` section whose body is **exactly** the block
below — no additions, omissions, or reworded lines:

```markdown
## Repository Context

This solution is defined by `/prism/config/repos.yml`. The repo containing this file is the `sdd` repo; the others are `code` repos.

Repos should carry a `/.context/` folder, a progressive-disclosure map of the code for agents. When investigating an unfamiliar repo, start at its `/.context/manifest.yml`, load only the `always-load` files and the modules whose `load-when` matches the task, then follow the links into source. Code wins over context when they disagree.
```

Reconcile the file to that text:

- **Section missing** — insert it, preserving surrounding content and heading
  order.
- **Section present but different** — replace its entire body with the block
  above, verbatim. Do not merge, append to, or preserve the previous wording.
- **Section already identical** — leave the file untouched and report it as
  unchanged.

Every other part of `/AGENTS.md` is out of scope: make no edits outside this
section.

## Omission rule

A missing file is meaningful signal. Never create empty, speculative, or
symmetry-only files. Omit any optional file that lacks evidence.

## Freshness

Note when the layer was last verified (in `README.md` or `manifest.yml`).
Re-verify when repos are added to or removed from `/.prism/config/repos.yml`,
or when a repo's role or `contextPath` changes.
